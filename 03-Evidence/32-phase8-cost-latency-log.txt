## 6. Cost/latency implications of hybrid retrieval and reranking

- **Hybrid (BM25 + RRF):** +0.11 ms per query (≈ 0.5 % of retrieval), $0 API cost, ≈ 2 ms one-time index build. Negligible.
- **Cross-encoder reranking:** +63 ms median per query on CPU (p95 69 ms) for v1 chunking; $0 API cost; one-time 92 MB download and ~0.2–0.8 s load; ~0.6 GB extra dependencies (torch). Relative to an LLM call of ≈ 1–2 s it adds ≈ 3–6 % to end-to-end latency.
- **LLM cost is unchanged** by retrieval choices because the context stays at 4 chunks; tokens per query are driven by chunk length and the answer.
- The dense refusal gate is the only component that *reduces* LLM cost (it skips the call), and on this evaluation set it never triggered for v1 (all 5 unanswerable questions were refused by the LLM itself).
